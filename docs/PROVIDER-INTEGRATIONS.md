# Provider integration details

For installation and first launch, follow the [README setup guide](../README.md#install). This page is a technical reference for the current source. Read [AGENTS.md](../AGENTS.md) before changing these paths. Current verification remains compilation and static review only.

## Connect Codex

QuotaBar locates the Codex CLI bundled in ChatGPT/Codex or a standalone installation and reads `account/rateLimits/read` through its local app server. This reuses the existing ChatGPT subscription sign-in. It also checks common npm, nvm, Volta, Bun and pnpm global folders. API-key-only authentication does not provide subscription limits.

## Five-hour limit applicability

The usage model distinguishes a measured five-hour window, a supported no-limit state and an unavailable reading. A current no-limit state shows neutral `∞` in the five-hour menu-bar position and **No 5-hour limit** in the popup, without a five-hour meter or reset time. Weekly usage and the exhausted-weekly countdown keep their existing behavior. The menu-bar item fits its content, so these transitions can change its width; a change waits until the popup closes. Stale or disconnected readings cannot supply current infinity; saved readings describe the state at their original timestamp.

Codex currently reports no five-hour limit for Pro plans. QuotaBar requires `planType: "pro"`, exactly one valid 10080-minute weekly window, and an explicit null in the other window slot. The weekly window may be `primary` or `secondary`; duration determines its identity. A reported five-hour window takes precedence. Other plans, omitted slots, malformed objects, invalid percentages and all-null windows remain unavailable. This narrow rule follows [OpenAI's current plan documentation](https://learn.chatgpt.com/docs/pricing) and the sanitized response-shape observation recorded in [verification status](VERIFICATION.md); it does not treat the Pro name alone as a permanent exemption.

Claude has no supported no-limit state. Its `get_usage` interface is experimental and leaves `five_hour: null` undescribed, and the documented [Agent SDK usage report](https://code.claude.com/docs/en/agent-sdk/typescript#sdkusagereport) describes applicable meters through the server's `limits` rows instead of `five_hour`. Static inspection of official Claude Code 2.1.310 showed that it passes endpoint nulls through unchanged, omits missing windows in its header-derived fallback, and can answer a failed fetch with an unmarked cached reading up to an hour old. Its own `/usage` views hide a null `five_hour` exactly like a missing one, and neither the CLI nor the documentation treats it as an absent limit. QuotaBar therefore keeps explicit `five_hour: null`, missing keys, malformed windows and percentages, and status-line and history omissions unavailable. A Claude no-limit state would need documented or live-verified provider evidence.

## Connect Claude

Installation discovery includes QuotaBar's managed Claude Code helper. It reads the non-secret saved release manifest and checks that the referenced executable file exists; an empty directory, missing helper or invalid manifest does not count. This lightweight visibility check never launches or hashes the helper. The normal helper loader still verifies its checksum before use.

Claude automatically reuses the official CLI's saved subscription sign-in at startup and on refresh, just like Codex. There is no separate **Use existing sign-in** choice. **Connect Claude** checks the saved sign-in and, only if needed, starts the official browser sign-in directly, without a second native window or another sign-in button. If a helper is missing, this explicit action prepares the verified official helper, then checks the saved login before signing in. Progress, cancellation and errors appear in the popup; **Sign-in help…** opens the optional recovery window for reopening the official authorization page or entering a browser-provided code. To change accounts, sign in to a different account in Claude Code; QuotaBar follows its saved sign-in. Browser login runs only `auth login --claudeai`; finish authorization yourself. Startup, polling and retrying usage never start browser sign-in.

**QuotaBar does not read Keychain credentials or call Claude's authenticated usage endpoint itself.** Claude Code manages its own normal saved sign-in. macOS may still require Claude Code itself to unlock or access its credentials; QuotaBar does not request that access or alter any Keychain permissions.

The usage reader starts a bounded Claude Code subprocess and sends only these control requests:

- `initialize`
- `get_binary_version`
- `get_usage` with `skip_behaviors: true`

When a usage read fails, a separate bounded `claude auth status` command checks the CLI’s reported authentication method and exit status. Only a confirmed signed-out or incompatible authentication method requests subscription sign-in. Unsupported status output, network/service failures, stale caches and version errors remain usage errors with a retry action. Raw status output stays in memory and is never displayed or logged.

It sends no user prompt, model turn, reset action, or authentication token. Tools, hooks, external MCP servers, project settings, customizations, telemetry, automatic updates, and session persistence are disabled for this reader. Managed policies remain effective. API keys and custom credential environments are not inherited. Do not use `--bare`: it disables subscription OAuth too. The CLI is responsible for its own credential handling; QuotaBar never refreshes or writes credentials itself. Background discovery never downloads a helper or starts browser sign-in.

This uses the experimental `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET` / `get_usage` interface that Anthropic added to its Agent SDK. The current reader requires CLI 2.1.309 or later because that is the locally inspected version with the skip-history behavior verified. Older or incompatible CLIs fail visibly. Claude usage still needs successful subscription authorization before live values can appear.

The result preserves five-hour/weekly usage, scheduled reset times, model windows, and extra usage whenever returned. The CLI is allowed to exit normally after a read so pending cache writes can finish before the sample timestamp is verified. Optional reset grants are parsed only if the CLI actually includes them. Missing grant inventory stays unknown and hidden; full reset-credit parity has not been verified through this route. Claude redemption continues to open the official Usage page for the user's own selection and confirmation.

Claude Code can answer from its own usage cache. QuotaBar reads only the non-secret account metadata and `cachedUsageUtilization` fields in `~/.claude.json`, matches the account and the returned quota windows, and preserves `fetchedAtMs`. It does not stamp an older CLI cache as newly fetched, including the unmarked reading up to an hour old that Claude Code can return after a failed fetch. A response needs a matching sample recorded during the request or a reused sample that remains less than 60 seconds old through read completion. The boundary is conservative: initialization and version checks precede `get_usage`, so a sample that crosses 60 seconds during helper startup may already be a failed-fetch fallback. It therefore fails the refresh immediately, even if it is still younger than two minutes. A new sample recorded during the request remains subject to the strict 120-second response-validation limit. A timestamp advance alone is insufficient when another writer restores an older sample. Missing provenance, a timestamp rollback, an in-flight account change or a newly returned sample at least two minutes old fails the refresh. Disk values remain historical until a CLI response is separately matched and validated.

On 28 October 2026, an authorized instrumented copy of 0.3.0 showed the official 2.1.310 helper receiving HTTP 429 and then returning cached usage through a successful control response. Static inspection found that its remembered HTTP-failure hold is local to that subprocess; it is lost when the helper exits. QuotaBar therefore keeps its own request deadline across helper launches. Production reads do not depend on debug logs or claim to identify the HTTP status from an unchanged cache alone. See the dated evidence and limitations in [verification status](VERIFICATION.md).

Dated observations and remaining acceptance work are recorded in [verification status](VERIFICATION.md). Live five-hour/weekly usage and automatic refresh have been observed locally; optional Claude reset-grant fields remain unverified.

## Antigravity

Antigravity support is experimental and covers subscription quota reported by its official CLI, including Gemini 4 groups when the provider supplies them. It does not query the separate Gemini CLI or Gemini API billing. [Issue #27](https://github.com/YogevSitton/quotabar/issues/27) tracks the integration.

### Reviewed helper and configuration workaround

Only the official macOS arm64 CLI **1.4.9** binary with SHA-256 `a66421b7962ffe5642e00cffdd2844dfde440e540502a29d206be5544a065c7b` is accepted. **Connect Antigravity** prepares a private copy from a matching installed CLI or Google's exact, SHA-512-pinned archive, then validates the binary hash and Google Developer ID signature. Polling never downloads, replaces or updates the helper. The source contains the pinned archive URL and checksum; changing the pin requires reviewing the protocol and startup behavior again.

The fixed request is `-p /usage --output-format json`. Static inspection found that a saved `disableSlashCommands: true` wins over `--disable-slash-commands=false` and can route this text into a model turn. The [upstream report](https://github.com/google-antigravity/antigravity-cli/issues/1361) records that defect. Checking `num_turns` afterward cannot prevent it.

QuotaBar instead owns a private filesystem profile under `~/Library/Application Support/QuotaBar/Antigravity`, with an explicit `HOME`, `--gemini_dir` and `--app_data_dir=quotabar`. The profile has known non-secret settings with slash commands enabled, empty MCP/hooks configuration, no global plugin registrations and an empty working directory. Default customizations and automatic CLI updates are disabled. A cross-copy lock covers configuration validation, request reservation, execution and completion. Before each read, QuotaBar removes leftover working-directory files, plugin, skill, workflow and rule registries, and agent instruction files from this private profile without following symlinks; the launch check immediately before the CLI starts only refuses them. Unsafe paths stop the read. If the profile cannot be verified, the popup offers **Retry**, which rechecks it within the saved request schedule; **Connect Antigravity** is only for setup and sign-in. Personal CLI settings and credential files are never read, copied or modified by QuotaBar.

The pinned CLI's recognized usage-command branch skips conversation creation and model turns. Its headless path skips the conversation-search index. Static review also established that the normal `cli` mode skips the IDE-only system MCP manager, and that the bundled customization registry contains skills but no plugins that add MCP servers. The official helper can still do its own read-only account/bootstrap work, including cloud summary/project metadata; this is not a claim that its only network request is the quota endpoint. QuotaBar consumes only the usage-command JSON and never logs raw output. System administrator policy lives outside this profile; the integration declines to launch while `/Library/Application Support/Antigravity/admin_settings.json` exists, rather than overriding it.

### Authentication and process boundaries

Monitoring uses `posix_spawn` with `POSIX_SPAWN_SETSID`, an EOF pipe on stdin, bounded output and a 45-second deadline. Both input properties matter: this CLI treats character devices, including `/dev/null`, as interactive, and otherwise tries `/dev/tty`. No controlling terminal and a real pipe prevent automatic browser sign-in even when QuotaBar was started from Terminal.

Only **Connect Antigravity** supplies an owned pseudo-terminal on stdin to the same fixed usage command, with a 180-second outer deadline. The official CLI then uses its normal saved-authentication and browser-login path, with optional manual code entry through QuotaBar. Codes are limited to the terminal's 1,023-byte line length. Cancel terminates the owned process group and clears the code. Output during sign-in may include a preamble; only a final top-level JSON object, on one line or pretty-printed, is parsed. No positional `agy login` or internal CDE auth shortcut is used: static inspection found that the latter's credential-file fallback differs from the normal CLI path. The CLI can reuse the shared `antigravity` Keychain service despite isolated `HOME`; QuotaBar does not promise a separate account or inspect that entry. Official CLI authentication remains subject to macOS's normal trust controls.

### Quota groups, freshness and scheduling

The parser requires `status: SUCCESS`, `command.name: usage`, numeric `num_turns: 0` and an `error` that is absent, empty or null. It reads dynamic `command.data.groups[].buckets[]`; it does not hardcode Gemini model IDs, combine pools, infer reset credits or classify omitted five-hour quota as unlimited. Multiple groups require an explicit popup selection. A missing saved selection never silently switches to another pool. Reported fractions must be finite and within 0...1; disabled, missing or malformed values remain unavailable. Count-only buckets do not become percentages.

The two menu slots recognize only unambiguous window text: `5h`, `5-hour`, `5 hours`, `weekly`, `7d` and `7 days`, ignoring case and surrounding whitespace. This is a conservative interpretation of duration text, not a claim that every label has been seen live. Other labels and independent buckets remain available in the resizable reported-quota view. Gemini 4 Argon is supported through this dynamic schema; its actual account-specific labels and quota availability remain unverified.

Static inspection established that `/usage` requests a fresh quota fetch, clears its old in-process cache and returns an error on fetch failure. The JSON has no account identifier or original server timestamp. QuotaBar conservatively records the local request start, holds readings only in memory, and does not claim account matching. An explicit connection or confirmed authentication boundary clears the old reading. A failure makes remaining values historical immediately; a past reset invalidates that window. Current readings expire after 390 seconds from request start.

Healthy requests start at least five minutes apart. Failures wait five minutes, doubling to at most one hour. A private durable record reserves each attempt as a possible failure before launch, shared across QuotaBar copies. A restart, wake, Retry or Connect cannot bypass it. Only a confirmed missing-authentication result from non-interactive monitoring proves that the quota request was not reached and permits immediate Connect. That authentication-only attempt also does not add to the failure count; earlier quota failures still count. An explicit sign-in preamble is never read as the final error. A Connect that exits with an error or returns no usable report therefore does not declare you signed out: it keeps its backoff and automatic retry, and **Connect Antigravity** is offered again at the same deadline. A cancelled or timed-out Connect may already have started a quota request, so its full deadline survives while background monitoring stays stopped. A cancellation that QuotaBar can prove happened before the official CLI started spends nothing and restores the earlier schedule. **Connect Antigravity** shows the wait and becomes available at that deadline, without starting sign-in by itself. Existing saved sign-in flags also retain their deadlines. Background waiting, signed-out and busy states skip helper hashing and signature checks; an explicit Connect still verifies or prepares its helper before the provider checks the saved schedule. These client intervals are conservative defaults, not a documented Google request allowance.

Official references: [headless behavior](https://antigravity.google/docs/cli/headless), [usage command](https://antigravity.google/docs/cli/commands/usage), and [Google's profile-isolation guidance](https://github.com/google-antigravity/antigravity-cli/issues/1080). The implementation-specific claims above come from static inspection of the exact pinned binary. No Antigravity provider call or sign-in was exercised during development; see [verification status](VERIFICATION.md).

## Refresh and local fallbacks

Codex polls every 60 seconds. Healthy Claude reads are spaced at least 130 seconds apart, measured from both the request start and the accepted sample time. This reduces QuotaBar's normal Claude request frequency by more than half compared with a one-minute interval. These are client intervals, not a known provider-supported request quota. Claude can still return HTTP 429, and other apps or machines do not share QuotaBar's local budget. No model inference requests are made.

Claude failures start a five-minute wait and double it on repeated failure to 10, 20, 40 and at most 60 minutes. A private, locked record shared by QuotaBar copies under the same local user reserves a request and its possible failure delay before the helper launches. It persists request timing and retry state without account identifiers or credentials. Only an accepted account-matched response releases the reservation onto the healthy cadence. A crash or restart cannot discard the reserved delay, and an unreadable or unwritable budget must not allow an unreserved request. Retry usage, wake, connection verification and account changes all respect the saved deadline. A newer cache sample does not bypass a waiting period.

Claude's dedicated timer schedules the exact next eligible read instead of dropping an early shared polling tick for a whole interval. The CLI still owns its own network handling and authentication; QuotaBar does not receive or override raw HTTP Retry-After headers through this interface. The dashboard, menu and Details window allow a successfully validated reading to remain current for less than 240 seconds from its original sample time. This covers the 130-second interval, a valid reused sample under 60 seconds old, the helper's 45-second timeout and five seconds of scheduling margin. Response validation remains stricter: this display allowance does not accept an expired cached fallback as a successful refresh. A failed refresh immediately makes current percentages unavailable while the original sample remains visible as **Saved reading**. A missed refresh or long system stall also expires the display at 240 seconds. A past reset time also suppresses that window's current percentage until a fresh reading arrives.

When Claude's live request is unavailable, the app selects the newest account-matched reading from:

1. The last successful usage response held in memory.
2. Claude Code's account-matched usage cache, retaining its original timestamp.
3. An optional Claude Code status-line snapshot.
4. `~/Library/Application Support/Claude/plan-usage-history.json` (version 2).

Disk history contributes percentages only: no reset times, credit counts, or expiries are inferred. Its original sample time is retained, even when it is hours old. Account/organization IDs are read from `~/.claude.json` only to keep readings from different accounts apart. A boolean unused-reset cache is not interpreted as a credit inventory because it cannot supply counts or expiry dates.

### Optional status-line exporter

`scripts/capture-claude-statusline.py` can receive Claude Code's status-line JSON and save only sanitized rate-limit fields, the active organization ID, and the capture time. It creates a private (0600) JSON snapshot at `~/Library/Application Support/QuotaBar/claude-statusline.json` using an atomic replacement. QuotaBar checks for changes every ten seconds and labels it **Saved reading** in the popup, with its original capture time. This requires an active Claude Code session to supply readings.

**The exporter is not installed or configured automatically.** Enabling it changes `~/.claude/settings.json` and requires your explicit consent. If you already use a status-line script, preserve or chain that script instead of replacing it. QuotaBar does not make this settings change for you.

Additional/model windows and extra usage are parsed defensively but deliberately not displayed. Optional reset-credit fields are schema support, not verified live behavior.
